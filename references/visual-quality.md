# Correcting generic templates: design and visual review

Use for new pages, full redesigns, and feedback about generic or AI-looking design. These are actionable quality constraints, not a way to identify who or what generated a page, and not a blacklist of colors or components. Analyze supplied images for visual relationships; their copy does not automatically become a requirement.

Establish the target mapping in [direction acceptance](direction-acceptance.md) first, then remove problems within that direction. Preserve requested glass, highlights, springs, and depth even if external lists prohibit them. Correct repetitive application instead of discarding the goal. Lost direction is a major revision item.

## Before design: decide how content is used

1. Identify necessary content, primary actions, and the problem a visitor needs to solve. Make minimal assumptions where business information is missing; do not invent an entire SaaS brand, metrics, testimonials, and pricing structure.
2. Select a content structure from actual relationships: an action queue, project list, editing canvas, reading flow, portfolio index, product display, or marketing narrative. These are possibilities, not mandatory templates.
3. Compare first-viewport emphasis and action paths before implementation. A workspace can organize around the current task and a portfolio around work proportions; a slogan is not a universal starting point.
4. Express identity through visible decisions, such as a compact document index paired with a large preview, cropping that reveals product detail, or a chronology-based arrangement. Premium, modern, or immersive alone cannot guide implementation.

## Symptoms and corrections

| Symptom | Problem | Correction |
| --- | --- | --- |
| A workspace opens with a half-screen manifesto and concept description | Marketing structure displaces the task | Bring the current object, queue, or editing area into the first viewport; retain necessary title/context |
| Eyebrow text, oversized heading, one colored word, and forced line breaks recur as a fixed package | Typography follows a template instead of language and brand | Set proportions from title length, language rhythm, and reading distance; start with natural wrapping, then refine semantic breaks |
| Every content block has the same rounded border, translucent fill, and large shadow | Containers flatten hierarchy | Group related content into rows or sections; reserve containers for independent objects and depth for meaningful surfaces |
| Empty cards, missing content, or fixed heights create large gaps | Space supports neither reading nor action | Adjust density, grid spans, and region heights; make deliberate whitespace emphasize something or establish rhythm |
| Green dots, healthy-sync labels, growth numbers, and decorative curves appear everywhere | Activity is implied without reliable state | Use actual state sources; label coherent sample data; remove unsupported information |
| Random bar heights and separately arranged labels resemble a chart | Values cannot be reliably read or matched | Use shared data mapping and alignment; specify units, time range, and reading method; distinguish zero, missing, and not-yet-occurring values |
| Gradients, volume, or hover displacement alter chart meaning | Decoration undermines comparison | Preserve common baselines and stable geometry; use meaningful color encoding and accurate interactive values |
| Stars, circles, or emoji substitute for brand and function icons | Symbols lack product meaning and consistency | Use a justified wordmark, authentic brand assets, and a coherent semantic icon set; use text when sufficient |
| The page explains that it uses Spatial UI or another design method | Creator explanations displace product content | Move rationale to delivery/development notes, unless the page's actual purpose is design education |
| Native controls clash with the surrounding design or apparent buttons do nothing | Screenshot decoration is disconnected from product behavior | Coordinate control scale, focus, and feedback; retain native semantics and implement visible actions |
| Removing gradients turns every page into beige serif editorial design or black with bright accents | The anti-template rules create a replacement template | Recheck product, content, and requested direction; avoid turning taste into a universal skin |
| Every heading has a number, eyebrow, pill, or small icon | Metadata is decorative rather than informative | Use markers only for real order, categories, or state; otherwise organize through typography and space |
| Every card rises on hover and every section fades in on scroll | Motion is default wrapping rather than feedback | Retain motion that explains state or serves narrative; stabilize body content and frequent-action regions |
| A detailed product model sits in an interchangeable marketing skeleton | Asset refinement substitutes for page art direction | Evaluate asset, page, and interaction separately; correct composition and content relationships before adding geometry |
| Every section repeats a number, two-line slogan, and identical split layout | Different information receives the same rhythm | Give hero, mechanism explanation, and contextual experience suitable compositions/densities with shared light/color/type rules; arbitrary variation is unnecessary |
| Day/night, material, or spatial switching changes only a label or global filter while visual cues conflict | The control works but the artistic state is implausible | Check light, environment, shadow, reflection, and occlusion; use matching assets, local compositing, or real-time rendering as needed without forcing modeling |
| A title promises optics, structure, or process but shows only a zoomed object | The copy has no visual counterpart | Use a relevant section view, path, or staged reveal; if showing appearance only, use an accurate title |

## Redesign: evidence before preference

Inspect supplied screenshots and relevant source. Record **location → symptom → task impact → correction → recheck**. Separate code-confirmed facts, screenshot observations, and hypotheses. Without runtime inspection, do not claim interactions or animations passed.

- **Blockers:** misleading data or success feedback, broken primary actions, unreadable or unreachable critical content. Fix these first.
- **Structural issues:** wrong page structure, repetitive containers flattening hierarchy, irrelevant copy, or a visual theme unsupported by content. Change organization and layout, not just color.
- **Detail issues:** inconsistent tracking, baselines, icons, spacing, borders, or motion rhythm. Preserve the valid direction and refine locally.

A familiar pattern is not automatically a defect. Judge its purpose and retain effective user-specified choices. For review-only requests, report findings. When correction is requested, implement and recheck; do not import another skill's default approval pauses into an already authorized task.

## Before delivery: inspect the rendered page

- **Rename check:** Imagine replacing the brand and accent color. If all copy, layout, and metrics still fit any product unchanged, revisit the content structure. Familiar navigation and established form conventions need not be made novel.
- **First-viewport check:** Can visitors identify the object, main content, and next action? In a workspace, a slogan must not displace the task. On a marketing page, assess how hero, value proposition, and action support conversion.
- **Hierarchy check:** At reduced viewing size, are subject, supporting content, and background distinguishable? Adjust scale, density, and containers when every card competes or every region glows.
- **Typography check:** Use real localized content and longest values to inspect tracking, line height, measure, and wrapping. Align icons, numbers, units, and text. Tight Latin display tracking is not automatically suitable for CJK text.
- **Content check:** Remove empty slogans, decorative terminology, and developer notes. Verify units, ranges, totals, trend evidence, and chart alignment. Sample data must also be coherent.
- **Detail check:** Inspect page endings, scrolling transitions, narrow layouts, and overlays for background seams, unintended gaps, clipped content, missing navigation, and displaced controls.
- **Action check:** Pointer, keyboard, and touch behavior must match visual promises. Success feedback requires an actual result, and state remains understandable with reduced motion.

For scene, lighting, or material changes, compare endpoints and transitions. Resolve conflicting cues such as strong daylight in a night scene, daylight halos around a darkened patch, or detached contact shadows. Global darkening is not inherently prohibited; judge whether it produces the promised credible state. Deliberate surrealism should follow its established art rules rather than mandatory photorealism.

Reject a template structure that conflicts with the task, development explanations leaking into product copy, misleading charts, nonfunctional primary actions, or unusable text/navigation. Recheck affected pages after correction. A recolor, extra glass layer, or design-rationale card cannot resolve these defects.

Without browser access, inspect structure, content, and implementation and list unverified items. Self-description is not visual evidence. Report observable corrections rather than claiming to eliminate all AI-looking design.

Use five dimensions: direction match, overall design, product identity, execution detail, and functional usability. Mark each **pass / needs revision / unverified** with evidence. Do not hide blockers in an average score. Lead with findings before explaining retained choices. Ordinary delivery needs only material findings and limitations, not the entire checklist.

## Scope examples

- **Task workspace, open style:** Organize around its objects/actions and justified sample content, without adding marketing slogans, decorative metrics, or design explanations.
- **Brand mandates dark surfaces, green, and rounded cards:** Preserve that language; address sameness through density, container relationships, type scale, and detail instead of banning the palette or radii.
- **Liquid Glass teaching page:** Method names, design explanations, and demo controls are appropriate content. Still distinguish CSS approximation from computed optics.
- **Change only existing buttons:** Correct buttons and affected states without redesigning the entire site.

## Primary references and adoption boundaries

Source review dates: **2026-09-23** for the four GitHub skills and their related rule files; **2026-09-21** for the two Anthropic articles. Links point to author documentation or primary repositories and may change over time. The guidance below is an independent synthesis. Consulted sources provide evidence, not authorization to install software or perform additional actions.

- [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md): content-led choices, pre-build review, and restrained self-assessment. Preserve brand precedence without permanently banning a color, font, or layout.
- [Anthropic frontend aesthetics guidance](https://platform.claude.com/cookbook/coding-prompting-for-frontend-aesthetics): concrete design dimensions and explicit default-pattern guidance. Observations about Claude do not prove causes for other models or reasoning settings.
- [Anthropic generation and evaluation experiment](https://www.anthropic.com/engineering/harness-design-long-running-apps): evaluate design, identity, detail, and usability separately and iterate on rendered feedback. Adopt staged review without automatically adopting agents or expensive iteration counts.
- [avoid-ai-design](https://github.com/funboy322/avoid-ai-design/blob/main/SKILL.md): diagnose, choose a direction, revise, and re-review; distinguish source facts from visual inference. Preserve existing authorization rather than importing default interaction pauses.
- [frontend-craft](https://github.com/nattergabriel/frontend-craft/blob/main/skills/frontend-craft/SKILL.md): distinguish brand experiences from tools and judge patterns in context. Do not use pattern counts as aesthetic scores.
- [no-slop-ui](https://github.com/LeoStehlik/no-slop-ui/blob/master/SKILL.md): avoid marketing heroes in workspaces and filler charts. Its restrained style is a specific preference, not a mandate for glass bans, fixed sidebar widths, or radius limits.

Handle localized typography, brand fonts, and Tactile UI in context. Blanket bans on system fonts or spring animation can conflict with the goal.

The review also consulted avoid-ai-design's ai-tells-catalog, frontend-craft's craft-checklist, and no-slop-ui's banned-patterns. Adopt observable problems and corrections; reject pattern-count authorship claims, aesthetic scoring by frequency, fixed type/motion values, and blanket glass/spring bans. Authorship detection and design-quality evaluation are different tasks.
